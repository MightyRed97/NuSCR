# 4 Code

The function-block design of `2_design/` implemented in C, with a command-line simulator, and in JavaScript for the virtual system in `START_HERE.html`. Both are generated from `2_design/rps_design.json` and compared with the requirements model scan by scan.

> SYNTHETIC REFERENCE DESIGN, not target code. The code runs the design on a desktop computer for simulation; its generator is not a qualified tool, and every constant is an ILLUSTRATIVE placeholder.

| Path | Contents |
|---|---|
| `src/` | C11 code generated by `tools/export_c.py`: `rps_blocks` (the 12 blocks), `rps_bp` and `rps_cp` (the modules, one call per block instance in the design's execution order), `rps_system` (BP_A..BP_D and CP_A with their connections), `rps_constants`, and `rps_meta` (name, type and offset of every input and signal). |
| `app/rps_sim.c` | The command-line simulator (written by hand, generic over the metadata). |
| `js/rps_engine.js` | The design in JavaScript, generated by `tools/export_js.py`; it runs in a browser and in Node.js. |
| `build/` | Compiler output; not kept in git. |

## Build

```sh
python -B tools/build_c.py              # Visual Studio's C compiler (found by vswhere), or gcc/clang
```

Or by hand from the package folder, with any C11 compiler (in a Visual Studio developer prompt for `cl`):

```sh
cl /std:c11 /W4 /O2 /I 4_code\src 4_code\src\*.c 4_code\app\rps_sim.c /Fo:4_code\build\ /Fe:4_code\build\rps_sim.exe
gcc -std=c11 -O2 -Wall -Wextra -I 4_code/src 4_code/src/*.c 4_code/app/rps_sim.c -o 4_code/build/rps_sim -lm
```

Create `4_code\build` first if it does not exist. `tools/build_c.py` treats every warning as an error; with `--analyze` it adds MSVC's static code analysis. Both are clean, and the code also builds with the clang bundled with Visual Studio (`--compiler clang`).

## Run

```sh
4_code\build\rps_sim.exe run SYSTEM 5_simulation\scenarios\loss_of_flow_4ch.csv trace.csv
4_code\build\rps_sim.exe run BP 5_simulation\scenarios\pzr_pressure_excursion.csv
4_code\build\rps_sim.exe interactive SYSTEM        # set inputs and run scans by hand; type help
4_code\build\rps_sim.exe list BP                   # every input with its nominal value, every signal
```

`run` replays a stimulus file (the scenario format of `5_simulation/`) and writes one row per scan with every computed signal; it exits with 2 on an invalid stimulus and 3 on a file error. `interactive` accepts `set BP.f_PZR_P 2400`, `step 40`, `watch CP_A.f_RT_Init,BP_A.th_PZR_P_HI_Trip`, `show PZR_P` and `reset`; an input that a connection drives (such as `CP_A.f_A_PZR_P_HI_Trip`) is shown with the value it receives.

## Use the code in your own program

```c
#include "rps_system.h"

RPS_System_State st;
RPS_System_Inputs in;
RPS_System_Signals out;
RPS_System_init(&st);                  /* power-up */
RPS_System_nominal_inputs(&in);
in.BP_A.f_PZR_P = 2400.0;              /* change an input */
RPS_System_step(&st, &in, &out);       /* one 50 ms scan */
if (!out.CP_A.f_RT_Init) { /* reactor trip initiated */ }
```

The generated code has no dynamic memory, no recursion and no loops; analog values are `double`, flags `bool` and counters `int32_t`. Thresholds made only of constants are evaluated exactly at generation time, as in the SCADE and OpenModelica exports.

## How it is checked

`python -B tools/verify_c.py` builds the simulator, replays every reference run on it (7 standard runs, plus the long back-to-back runs of the design verification that fire every transition of the requirements model) and compares every computed signal in every scan with the NuSCR requirements model and, bit for bit, with a double-arithmetic reference. `python -B tools/verify_js.py` does the same for the browser engine under Node.js. Results: `6_verification/c_verification_report.json` and `6_verification/browser_engine_report.json`.
