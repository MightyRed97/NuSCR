# Opening the design in Ansys SCADE Suite

> STATUS: SYNTHETIC REFERENCE DESIGN. Every constant is an ILLUSTRATIVE placeholder. Not for operational, licensing or safety-classified use without full independent V&V.

SCADE Suite cannot read `design/rps_design.json`. It has no generic JSON or XML importer. This folder therefore contains the design as a Scade 6 text model, plus simulator scenarios to check it once it is loaded.

| File | Contents |
|---|---|
| `RPS_Design.scade` | Scade 6 textual model, package `RPS`. It holds the constants, the 12 design blocks as operators (6 `function`s, 6 `node`s), and the root-able operators `BP` (bistable processor) and `CP` (coincidence processor). |
| `scenarios/*.sss` | Simulator scenario scripts. Each sets every input in cycle 0 and afterwards only the inputs that change (the simulator keeps an input's last set value). It checks every output in every cycle (`SSM::check`) against the value computed by the NuSCR requirements model. |
| `scenarios/expected_float64_deviations.txt` | Checks that are expected to fail in SCADE's float64 simulation (see step 6). |

All files are generated by `python -B tools/export_scade.py` (run by `tools/build_all.py`). Do not edit them by hand.

## Steps

1. Create a new, empty SCADE Suite project.
2. In File View, right-click the Model Files folder, choose Insert Files and select `RPS_Design.scade`. The menu command Insert > Files also works.
   - The operators load read-only. To change them, edit the text file (double-click it in File View), or better, change `tools/build_design.py` and regenerate.
   - If SCADE reports a syntax error, nothing from the file is loaded until it is fixed. Please report the message (see "What has and has not been verified").
3. Select the package `RPS` and run the Checker: press F3, or right-click and choose Check. Checking the package checks every root operator in it. Errors must be fixed before simulation.
   - Warnings do not block simulation unless the configuration sets warnings as errors. Warnings that may appear and are expected are listed under "Checker and Rules Checker messages" below.
4. In the Code Generator toolbar, make the Simulation configuration the active configuration. Click Settings in the same toolbar, and on the General tab set Root operator to `RPS::BP` for the `bp_*` scenarios or `RPS::CP` for the `cp_*` scenarios. Choosing a configuration in the Settings window's own drop-down list only edits that configuration; it does not make it active. Click Run in the Code Generator toolbar, and rebuild the simulation executable when asked.
5. Make failed checks visible. In Tools > Options > Simulator, under Run-time events (On failed check/assertion/FP operation), choose Log only. The default is Ignore, which hides failed checks. With Log only the run continues to the end and every failure is listed in the Simulator tab of the Output window. Stop simulation also works, but it halts at the first failure, including the 2 expected ones in `bp_random_boundary_seed1.sss`.
6. In the Simulator Extension toolbar, click Load scenario and choose a scenario file. Then click Go in the Simulator toolbar to play it continuously, or Step to play it one cycle at a time.
   - Run each scenario in a fresh simulation session, from cycle 0. Every scenario assumes the operator's initial state (no latched trips, setpoints at their initial values). Before loading the next scenario, click Stop in the Simulator toolbar, then Run in the Code Generator toolbar again. Changing between `RPS::BP` and `RPS::CP` also needs a new session (step 4).
   - Every output is checked in every cycle, so a clean run shows that SCADE's execution of the model matches the NuSCR requirements.
   - The only failures to expect are the float64 rounding effects listed in `scenarios/expected_float64_deviations.txt`. At present that is 2 checks of the low SG1 pressure trip (`th_SG1_P_LO_Trip`) in `bp_random_boundary_seed1.sss`. There, a manual-reset setpoint computed at run time equals the process value exactly in decimal but differs from it by one rounding step in binary.
   - Cycle numbers: the scenario files number cycles from 0 (`# cycle 439`), while SCADE's cycle counter starts at 1. The two expected failures are file cycles 439 and 440, which SCADE counts as cycles 440 and 441. The deviation list gives both numbers and the file line of each check.
   - Any other failure is not explained by floating point and must be investigated.

| Scenario | Root | Cycles | Purpose |
|---|---|---|---|
| `bp_pzr_pressure_excursion.sss` | BP | 61 | Pressure excursion: pre-trip, trip, hysteresis, reset |
| `bp_cooldown_manual_reset.sss` | BP | 151 | Depressurisation with manual setpoint resets and operating bypass |
| `bp_loss_of_flow_channel_A.sss` | BP | 31 | Channel A in the four-channel loss-of-flow scenario |
| `bp_boundaries.sss` | BP | 1302 | Every analog trip and pre-trip comparator held exactly at its threshold, exactly at its reset threshold, and just beyond |
| `bp_random_boundary_seed1.sss` | BP | 1000 | Randomised run including values placed on the moving setpoints |
| `cp_loss_of_flow.sss` | CP | 31 | Coincidence processor in the loss-of-flow scenario (reactor trip initiation at cycle 15) |
| `cp_random_seed1.sss` | CP | 1000 | Randomised trips, bypass requests and link failures |

The scripts use `SSM::set_tolerance real=1e-9`, an absolute tolerance that applies to every real-valued output (the variable setpoints). Flags are compared exactly.

## Checker and Rules Checker messages

These do not affect Check (F3), simulation or code generation, but may be reported:

- **Instance Name warnings.** The Checker's instance name check may warn (category Instance Name) that an operator is called several times without an instance name. `BP` calls `FB_TRIP_BISTABLE` 30 times and `CP` calls `FB_VOTE_2OO4` 15 times, for example, and the calls are not named. SCADE Suite can compute instance names for textual models. The export does not name them itself, because the documented textual form for instance names is not settled.
- **Unused interface items.** `BP` has the 15 trip channel bypass switch inputs `f_<X>_Byp_Sw` in its interface but does not read them, because they go straight to the CPs. The 14 hysteresis constants `k_<X>_<W>_Hys` of the fixed-threshold trips and pre-trips are not referenced in any equation, because their values are folded into the pre-computed reset thresholds `k_<X>_<W>_Reset`. Any warning about these is expected.
- **Rules Checker (optional).** SCADE Suite's predefined design rules would flag the naming and the literals. Lowercase constant names such as `k_PZR_P_HI_Trip_SP` fail SDR-21 (uppercase constants). Block names such as `FB_TRIP_BISTABLE` are not PascalCase (SDR-11-12-1), and signal names such as `f_NPWR_LIN` are not camelCase (SDR-11-12-2). The literals `true`, `false`, `0`, `1` and `0.0` in operator bodies fail SDR-52. If the Rules Checker is used, deselect these rules or record one justification per rule: the names keep the NuSCR names for traceability, and the literals are initial values and boolean constants. If other names are required, change `tools/export_scade.py`, not the generated file.

## Other routes into SCADE Suite

- **Editable operators.** For each operator, declare its inputs, outputs and locals in Scade View, then use Insert > Text Diagram, paste the equations from `RPS_Design.scade` and choose Apply. Text diagrams stay editable, but SCADE cannot convert them to graphical diagrams.
- **Scripted creation.** The SCADE Python API, with the `ansys-scade-apitools` library, can create textual or graphical operators in an existing project from a script run with `scade -script`. It needs a licensed SCADE installation and must not be run against a model that is open in the IDE.
- **Code generator on the text file.** The SCADE Suite User Manual documents running the KCG executable directly on `.scade` files: `kcg<version> [options] -root <NodeName> <files>`.
- **Scade One.** The newer Scade One product imports a SCADE Suite project (`.etp` with its `.scade` files) into its own language, Swan, provided the project passes the SCADE check.

## How the text maps to the design

- One operator per design block. Parameters are extra inputs, placed after the block inputs. `DELAY` is an `int32` constant in scans (`k_<X>_<W>_Delay_Scans`).
- The design's `last_S` is written `last 'S`, and `S` is declared `S : T last = <initial value>`. All initial values are constants.
- A conditional single assignment becomes a nested `if ... then ... else ...` expression.
- Flags are `bool`. The design's `X = 1` becomes `X` and `X = 0` becomes `not X`. Trip signals are `true` = NORMAL, `false` = TRIP.
- Analog values and constants are `float64`.
- Constant-only threshold expressions such as `SP - HYS` are evaluated exactly at export time and emitted as named constants (`k_<X>_<W>_Reset`). Each threshold is then rounded once, rather than computed in float64 at run time. This removed all fixed-threshold float64 deviations.
- The `BP` operator's inputs are the NuSCR BP inputs. Its outputs are the NuSCR BP outputs except the trip channel bypass switches `f_<X>_Byp_Sw`, which are BP inputs passed straight to the CPs. `CP` takes each channel's trip signals, bypass requests and link diagnostics.

## What has and has not been verified

This package has no SCADE licence, so the file has not yet been loaded into SCADE Suite. It was checked with `tools/scade_subset.py`, a local parser, type checker and simulator for the part of the Scade 6 language the exporter emits:

- The file parses, and type-checks with no errors (single types per operation, no int/float mixing, `last` only on declared memories, functions calling only functions).
- Simulated with exact arithmetic, the `BP` and `CP` operators match the proven design in every signal and every scan (randomised and scenario runs). Every scenario's checks pass.
- Simulated with IEEE-754 double arithmetic, the only deviations are the ones listed in `scenarios/expected_float64_deviations.txt`.
- Fault injection confirms these checks catch export errors. Every one of the 52 trip and pre-trip comparator strictness errors (`>=` versus `>`, `<` versus `<=`) is caught by `bp_boundaries.sss`, and wrong initial values, int/float mixing and missing memory declarations are caught too.
- Every construct was compared with the public Ansys documentation and matches documented syntax:
  - The model file was checked against the Scade Language Primer (2025 and 2026 editions) and the SCADE Suite User Manual. This covers the package and constant block, negative constants, untyped numeric literals, operator headers, `last` declarations and `last 'x`, functions called from nodes, nested `if` expressions, `--` comments and uppercase identifiers.
  - The scenario scripts were checked against the SCADE Suite Technical Manual and the SCADE Test User Manual. Paths are package-qualified (`RPS::BP/<name>`), values are `true`/`false` and plain decimals, and `SSM::set_tolerance real=1e-9` has no path, so it applies to all outputs. Checks are registered before the `SSM::cycle` they apply to, and comments are whole lines starting with `#`.

Not yet confirmed until SCADE Suite checks the file:

- Acceptance of the file by SCADE's own parser and Checker. The syntax matches the documentation, but the full keyword list (Scade Language Reference Manual) is not public. Names such as `IN`, `MIN`, `MAX`, `RESET` and `DELAY` are assumed not to be reserved, because Scade is case-sensitive and its keywords are lowercase.
- Whether loading a `.sss` file resets the operator's memories. The manual documents a reset only for state files (`.sts`), which is why step 6 starts each scenario in a fresh session.
- How long the largest scenarios take to play. `bp_boundaries.sss` is about 2.5 MB and 61,000 lines, and no size limit is documented.
- That SCADE's float64 simulation rounds exactly as IEEE-754 double arithmetic in the order written. This depends on the code generator and the C compiler settings, and the deviation list assumes it. The model has no multiplications or divisions, so a fused multiply-add cannot change results.

If step 3 or step 6 reports anything outside `expected_float64_deviations.txt`, record the message. The fix belongs in `tools/export_scade.py` or the design, not in the generated file.
