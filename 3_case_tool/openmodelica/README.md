# OpenModelica model

`RPS.mo` is the function-block design as one Modelica package, to open, inspect and simulate in OMEdit, the OpenModelica Connection Editor. It uses no library, so it opens in any Modelica tool. It is generated by `tools/export_modelica.py`; don't edit it by hand.

> SYNTHETIC REFERENCE DESIGN. Every constant is an ILLUSTRATIVE placeholder. Not for operational, licensing or safety-classified use.

## What is in the package

| Class | Contents |
|---|---|
| `RPS.Constants` | The constants the design uses, the delays in scans, and the thresholds folded from constants (same names as in the C and SCADE code). |
| `RPS.Interfaces` | Boolean, Integer and Real input and output connectors. |
| `RPS.Blocks` | The 12 function blocks, and expression blocks that show an instance's expression inputs (for example a trip condition) in the diagram. |
| `RPS.BP_Groups`, `RPS.CP_Groups` | One model per FOD group (17 in the BP, 16 in the CP), wiring that group's block instances. The diagram of `RPS.BP_Groups.g_PZR_P_HI` shows the high pressurizer pressure trip, for example. |
| `RPS.BP`, `RPS.CP` | The modules: their inputs, outputs and FOD groups. |
| `RPS.System` | BP_A..BP_D and CP_A with the connections of the requirements. It is partial: a scenario supplies the inputs. |
| `RPS.Scenarios` | Three scenarios to simulate, each with stimulus blocks that replay its inputs, one value per scan. |

## Open and simulate it in OMEdit

1. Start OMEdit (Start menu: OpenModelica > OpenModelica Connection Editor).
2. File > Open Model/Library File(s), and choose `RPS.mo`. The package appears in the Libraries Browser.
3. Expand `RPS.BP_Groups` and double-click a group, for example `g_PZR_P_HI`. The Diagram View shows its blocks; the Text View shows the same in Modelica.
4. Expand `RPS.Scenarios`, open `PzrPressureExcursion` and click Simulate (the green arrow). The stop time and the 50 ms output interval are preset.
5. In the Plotting tab, tick `stim.f_PZR_P`, `bp.th_PZR_P_HI_Pretrip` and `bp.th_PZR_P_HI_Trip`. Flags are 1/0; trip signals are 1 = NORMAL, 0 = TRIP.

| Scenario | What happens | What to plot |
|---|---|---|
| `PzrPressureExcursion` | Pressure rises to 2360 psia (pre-trip) and 2400 psia (trip), holds inside the hysteresis band, then recovers. | `stim.f_PZR_P`, `bp.th_PZR_P_HI_Pretrip`, `bp.th_PZR_P_HI_Trip` |
| `CooldownManualReset` | Controlled depressurisation; the operator lowers the low-pressure setpoint step by step, then bypasses the trip below the permissive. The trip never actuates. | `stim.f_PZR_P`, `bp.g_PZR_P_LO.h_PZR_P_LO_Trip_SP`, `bp.th_PZR_P_LO_Trip`, `bp.g_PZR_P_LO.h_PZR_P_LO_OB_Sta` |
| `LossOfFlow4ch` | Coolant flow falls in all four channels; each BP trips and the CP initiates a reactor trip. | `stim_BP_A.f_SG1_F`, `BP_A.th_SG1_F_LO_Trip`, `CP_A.f_SG1_F_LO_Coinc`, `CP_A.f_RT_Init` |

The stimulus values are parameters, so you can change them in the parameters dialog (or the Text View) and simulate again. For each input there are two lists: `stim.f_PZR_P_at` holds the scans, in increasing order and starting with 0, at which `f_PZR_P` takes a new value, and `stim.f_PZR_P_v` holds the value from each of those scans on. `_v` takes its size from `_at`, so add or remove entries in both; a scan is 50 ms (scan 20 is at t = 1 s).

## How the model works

- Every block executes once per scan, at the instants of `sample(0, RPS.Constants.T_scan)` (every 50 ms from t = 0). Its body is one when-clause in which each statement of the design is one equation, and `last_S` (the previous-scan value of state `S`) is `pre(S)`. Outputs hold their value between scans.
- Within one sample instant Modelica sorts the equations of all blocks by data flow, which gives the same-scan transfers of the design. Stateless blocks are computed in the when-clause too, so every block output changes only at a scan.
- Values before the first scan are start values (false or 0); the first scan is at t = 0.

## How it is checked

`python -B tools/run_openmodelica.py` writes one verification model per reference run (`build/RPS_Verification.mo`), has OpenModelica compile and simulate each one with CSV output, and compares every computed signal in every scan with the NuSCR requirements model. It runs all 17 reference runs, which together fire every transition of the requirements model, in about 5 minutes; `--quick` runs only the 7 standard ones. The report is `6_verification/openmodelica_verification_report.json`. With OpenModelica 1.27.1 all 17 runs pass (3,039,070 comparisons): every flag equals the double-arithmetic reference and every real is within 1e-9 of the exact model. The only differences from the exact requirements model are 243 floating-point rounding effects, each listed in the report and each shown by the double-arithmetic reference too. Without OpenModelica, `6_verification/tests/test_modelica_export.py` checks that `RPS.mo` is current, and simulates one run when OpenModelica is installed.

On its very first start, OpenModelica copies the libraries bundled with its installer into `%APPDATA%\.openmodelica\libraries` and fetches its library index (`index.json`) from libraries.openmodelica.org. `RPS.mo` uses no library, and the scripts here never ask OpenModelica to download or install anything.
